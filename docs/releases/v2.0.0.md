# Release Notes v2.0.0

Dokumen ini merangkum perubahan antara `v.1.0.0` dan `master` sebagai bahan release v2.

Perbandingan sumber:
- Base: `v.1.0.0`
- Target: `master`

## Ringkasan

Release v2 berfokus pada penguatan alur operasional `Job`, `Job Product`, `Edit Amount Approval`, `PO Stock - Sample`, dan `Return Stock`. Selain penambahan fitur, release ini juga membawa perubahan struktur data, validasi yang lebih ketat, dokumentasi internal untuk beberapa modul utama, serta perbaikan integritas data pada dashboard dan inventory.

## Update Utama

### 1. Job Product ditingkatkan dan dipindah ke basis `products`
- Job Product sekarang menggunakan `product_id` sebagai relasi utama, bukan lagi bergantung pada `inventory_stock_id` untuk flow aktif.
- Form Job Product dapat ditambahkan langsung saat create Job, bukan hanya dari halaman edit.
- Tab Product pada Job mendukung add, edit, delete, dan export invoice dengan query berbasis `products`.
- Product dengan stok `0` tetap bisa dipilih di Job Product selama sesuai filter kategori dan supplier.
- Ketergantungan pada warehouse untuk flow Job Product dihilangkan.

Dampak bisnis:
- pencatatan product pada Job menjadi lebih stabil,
- flow create Job menjadi lebih lengkap dalam satu proses,
- invoice lebih konsisten dengan data product yang dipilih pada Job.

### 2. Create Job sekarang mewajibkan minimal satu Job Product
- Halaman create Job untuk source `Inquiry`, `Non Inquiry`, dan `Reguler` sekarang memiliki section input Job Product.
- Penyimpanan Job dan item product dilakukan dalam satu transaksi.
- Setelah Job berhasil dibuat, user diarahkan ke tab Product pada Job terkait.

Dampak bisnis:
- mengurangi Job yang terbentuk tanpa detail product,
- memastikan data awal Job lebih siap diproses ke tahap berikutnya.

### 3. Modul Edit Amount Approval diperluas
- User dengan permission yang sesuai dapat membuat request perubahan amount pada Job.
- Satu Job sekarang dapat memiliki banyak histori request edit amount.
- Sistem tetap menjaga agar hanya ada satu request berstatus `waiting` pada satu waktu untuk tiap Job.
- Halaman approval ditingkatkan, termasuk dukungan pencarian data yang lebih baik.
- Perubahan amount tidak langsung diterapkan; nilai `jobs.amount` baru diubah saat request di-approve.

Dampak bisnis:
- approval perubahan amount lebih terkontrol,
- histori audit permintaan perubahan amount tersimpan lebih lengkap.

### 4. PO Stock - Sample diperketat
- Edit PO dipindah dari modal ke halaman dedicated.
- Validasi create/update PO diperketat agar product harus sesuai dengan supplier dan main category PO.
- `store` dan `update` dibungkus transaksi database untuk mencegah partial write.
- PO yang sudah `complete` atau sudah terpakai transaksi turunan dibatasi agar tidak bisa diedit sembarangan.
- Pencarian PO Sample ditingkatkan, termasuk pencarian berdasarkan supplier.

Dampak bisnis:
- mengurangi mismatch data antara PO, supplier, kategori, dan product,
- menurunkan risiko inkonsistensi saat PO sudah dipakai modul turunan.

### 5. Return Stock / Sample ditambahkan ke Inventory Stock
- Halaman Inventory Stock dan Inventory Sample sekarang mendukung aksi return langsung dari daftar stok.
- Return stock divalidasi terhadap ketersediaan stok aktual.
- Flow return terhubung ke pencatatan `Other Income` melalui session sementara sebelum finalisasi.
- Penghapusan return akan mengembalikan qty stok ke inventory.

Dampak bisnis:
- pengembalian stok/sample menjadi tercatat,
- koreksi stok dan pencatatan nominal return lebih terkontrol.

### 6. Dashboard target achievement diperbaiki
- API chart target achievement sekarang menolak tahun di luar rentang valid.
- API chart bulanan menolak bulan di masa depan.
- Update data `sales_target_monthlies` diperbaiki agar lebih aman terhadap duplikasi.

Dampak bisnis:
- chart dashboard lebih stabil,
- integritas data target bulanan lebih terjaga.

### 7. Perbaikan inventory dan costing
- Perbaikan stale data pada `inventory_stocks.history_overall_qty`.
- Supplier option pada form add cost diperbaiki.
- Dokumentasi dan penelusuran alur Inventory In serta Inventory Stock diperjelas.

## Perubahan Database dan Data

Release ini membawa migration penting berikut:
- `2026_02_06_135835_clean_duplicates_and_add_unique_to_sales_target_monthlies`
  - membersihkan duplikasi `sales_target_monthlies`,
  - menambahkan unique constraint pada kombinasi `user_id` dan `month`.
- `2026_03_13_090000_update_jobs_has_products_table`
  - perubahan struktur pendukung untuk flow Job Product.
- `2026_03_16_110000_make_jobs_id_auto_increment`
  - menyesuaikan `jobs.id` menjadi auto increment.
- `2026_03_17_120000_migrate_job_products_to_product_id`
  - menambahkan dan melakukan backfill `product_id` pada `jobs_has_products`.
- `2026_05_08_000001_drop_unique_index_from_job_edit_amount_approvals_job_id`
  - melepas unique index lama agar satu Job dapat memiliki banyak histori request edit amount.

Catatan penting:
- `inventory_stock_id` pada `jobs_has_products` masih dipertahankan sebagai backup legacy.
- Terdapat draft cleanup migration untuk menghapus legacy field setelah validasi produksi selesai.

## Risiko dan Catatan Upgrade

- Release ini mengandung perubahan schema dan migrasi data pada `jobs_has_products`, sehingga perlu validasi data historis setelah migrate.
- Flow `Job Product` berubah signifikan; area create Job, edit Product, dan export invoice perlu dites end-to-end.
- Flow edit PO juga berubah dari modal ke halaman penuh; user operasional perlu diinformasikan.
- Karena ada perubahan pada aturan approval amount, permission user terkait request/review perlu dicek ulang sebelum release.

## Rekomendasi Validasi Sebelum Release

1. Jalankan seluruh migration pada environment staging dan verifikasi data `jobs_has_products` hasil backfill `product_id`.
2. Uji create Job untuk source `Inquiry`, `Non Inquiry`, dan `Reguler`, termasuk minimal 1 Job Product.
3. Uji add/edit/delete Job Product serta export invoice pada Job lama dan Job baru.
4. Uji request edit amount, approval, rejection, dan histori multi-request pada Job yang sama.
5. Uji create dan edit PO Stock/Sample, termasuk kasus product mismatch, supplier mismatch, dan PO yang sudah terpakai.
6. Uji return stock dari Inventory Stock dan Inventory Sample, termasuk pengaruhnya ke stok dan flow Other Income.
7. Uji chart dashboard untuk input tahun/bulan valid dan tidak valid.
