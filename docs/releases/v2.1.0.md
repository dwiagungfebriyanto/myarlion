# Release Notes v2.1.0

Dokumen ini merangkum perubahan antara baseline dokumentasi `v2.0.0` dan sistem ter-update saat ini pada branch `staging-master` sebagai bahan release `v2.1.0`.

Perbandingan sumber:
- Base: `v2.0.0` document baseline
- Target: current `staging-master` / current system snapshot

Catatan:
- Tag git terakhir yang tersedia di repository masih `v.1.0.0`.
- Dokumen release ini tetap memakai baseline `v2.0.0` agar konsisten dengan release note terdokumentasi yang sudah ada.

## Ringkasan

Release `v2.1.0` berfokus pada penguatan modul `Inventory Stock`, `Inventory Sample`, `Free Sample`, dan `Product`, disertai perubahan operasional pada bootstrap database. Dibanding release sebelumnya, perubahan kali ini lebih bersifat ekspansi fitur, peningkatan visibilitas histori stock, penyempurnaan validasi transaksi sample, perapihan dokumentasi teknis, serta adopsi schema dump `mysql-schema.sql` sebagai baseline environment baru.

## Update Utama

### 1. Inventory Stock diperluas dengan grouping, filter, dan history
- Inventory Stock sekarang mendukung filter `Warehouse` yang lebih jelas untuk operasional harian dan audit.
- List stock reguler diperbarui agar lebih informatif, termasuk kolom supplier dan bucket stock.
- Quantity operasional pada inventory stock sekarang mengikuti penggabungan berdasarkan `SKU - PO - Warehouse`.
- Tersedia halaman `History` untuk menelusuri ledger stock secara kronologis.
- Tampilan qty dan histori diperbaiki agar lebih konsisten untuk pembacaan saldo.
- Perbaikan UI dilakukan pada interaksi filter warehouse agar halaman inventory stock tidak rusak saat filter diklik.

Dampak bisnis:
- penelusuran asal-usul dan mutasi stock menjadi lebih mudah,
- list inventory cukup menjadi tampilan operasional utama tanpa halaman agregat terpisah,
- proses audit stock lintas warehouse menjadi lebih aman.

### 2. Inventory Sample disejajarkan dengan perilaku Inventory Stock
- Inventory Sample sekarang mengikuti pola list yang sama dengan Inventory Stock, tetapi tetap dibedakan oleh `stock bucket = sample`.
- Ditambahkan halaman `Sample History` khusus untuk ledger sample berbasis supplier, product, dan warehouse.
- Struktur tampilan history sample disejajarkan dengan history stock agar lebih konsisten saat dianalisis user.
- Dokumentasi modul Inventory Sample dan Inventory Sample History ditambahkan untuk memperjelas perilaku aktif sistem.

Dampak bisnis:
- sample lebih mudah dilacak sebagai inventory tersendiri,
- histori sample lebih mudah dibaca oleh tim gudang dan tim audit,
- user tidak perlu mengandalkan interpretasi manual dari row inventory aktif.

### 3. Free Sample diperluas menjadi lebih fleksibel dan lebih aman
- Free Sample sekarang mendukung dua mode recipient:
  - `by inquiry`
  - `by customer`
- `customer_id` dapat bernilai `null` untuk inquiry customer baru yang belum memiliki master customer.
- Source Free Sample sekarang bisa berasal dari inventory stock yang siap dipakai, tidak terbatas pada jalur sample tertentu.
- Halaman list Free Sample mendapat tambahan kolom `Inquiry Date`.
- Validasi quantity, recipient, dan keterkaitan inquiry diperketat.
- Error handling di form diperjelas agar kegagalan submit dapat dibaca langsung dari modal.
- Proses simpan dibungkus transaksi dan lock stock untuk mengurangi risiko saldo tidak sinkron.

Dampak bisnis:
- distribusi sample gratis di luar job menjadi lebih fleksibel,
- transaksi untuk inquiry customer baru tetap bisa dicatat tanpa memaksa pembuatan customer lebih awal,
- risiko oversubtract stock dan mismatch penerima menjadi lebih rendah.

### 4. Modul Product diperjelas sebagai master SKU lintas modul
- Dokumentasi Product baru ditambahkan untuk menjelaskan peran modul sebagai sumber master SKU bagi inventory, PO, dan job.
- Halaman Product List sekarang menampilkan panel informasi SKU agar format kode lebih mudah dipahami user internal.
- Kode supplier pada SKU diubah menjadi 4 digit.
- Endpoint opsi product dan dropdown relasi pendukung tetap menjadi fondasi integrasi untuk modul lain.

Dampak bisnis:
- format SKU lebih mudah dijelaskan dan diaudit,
- user mendapat konteks yang lebih jelas saat membaca atau memverifikasi kode product,
- konsistensi identitas product lintas modul meningkat.

### 5. Integritas cost inventory diperbaiki
- `inventory_stocks.purchase_cost` untuk stock PO sekarang menjadi reference total per produk dari detail PO, bukan valuasi saldo aktif.
- Pengurangan, pengembalian, dan transfer stock menjaga reference cost tetap sama walaupun quantity berubah atau menjadi nol.
- Stock tanpa lineage PO tetap menggunakan total cost yang bergerak proporsional dengan quantity.
- Snapshot cost Free Sample dan Job Statement menyimpan unit cost source saat transaksi dibuat.
- Service legacy `StockUpdateService` dihapus karena flow aktif sudah menggunakan service saldo inventory terpusat.
- Ditambahkan data migration `2026_06_15_120000_fix_inventory_cost_integrity` untuk memperbaiki data historis yang cost-nya tidak lagi konsisten dengan `inventory_ins`.

Dampak bisnis:
- reference cost stock konsisten dengan total produk pada PO di setiap warehouse,
- snapshot transaksi tetap memakai unit cost source sehingga biaya pemakaian stock tidak berubah,
- koreksi data dapat diaudit dan di-rollback secara terarah melalui backup internal migration.

## Perubahan Database dan Deployment

Release ini bukan release yang berat di migration incremental biasa. Perubahan operasional yang paling penting justru ada pada cara bootstrap database untuk environment baru.

Perubahan utama:
- Repository sekarang memakai baseline schema `database/schema/mysql-schema.sql`.
- Migration historis sebelum baseline tidak lagi dipertahankan di jalur `database/migrations`.
- Folder `database/migrations` sekarang dipakai hanya untuk migration baru setelah baseline schema.
- README dan README_DEV diperbarui untuk menjelaskan workflow import schema lalu lanjut migrate untuk perubahan baru.
- Migration koreksi cost inventory menyimpan backup row terdampak di tabel `inventory_cost_integrity_backups_20260615`.
- Koreksi reference cost PO digabung ke migration koreksi cost inventory yang sama dan tidak membuat tabel backup tambahan.

Implikasi deployment:
- environment baru tidak diasumsikan melakukan full migrate dari nol,
- alur yang direkomendasikan adalah import snapshot schema terlebih dahulu,
- setelah import baseline, barulah jalankan migration baru yang memang dibuat setelah baseline tersebut.

Catatan penting:
- perubahan ini menyederhanakan provisioning environment baru,
- perubahan ini juga berarti tim deployment harus menghindari asumsi lama bahwa seluruh histori schema tersedia sebagai migration runnable.
- untuk deployment manual koreksi cost, jalankan maintenance mode lalu `php artisan migrate --force`; patch SQL manual tidak perlu dijalankan.
- backup internal migration tidak menggantikan backup database penuh sebelum deployment production.
